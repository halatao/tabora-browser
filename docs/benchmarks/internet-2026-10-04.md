# The Internet online compatibility pilot — 2026-10-04

**The official extension with the calling Codex agent completed 9/9 valid tasks. Tabora’s internal raw-goal controller completed 1/9 with Codex Luna and 0/9 with Jev.** This result contradicts any broad stability claim inferred from the earlier three retrieval tasks.

The externally maintained [The Internet](https://the-internet.herokuapp.com/) ([source](https://github.com/tourdedave/the-internet)) supplies the pages. These ten goals and the scoring are authored for this pilot; this is neither WebArena nor an official independent benchmark.

## Protocol and limitations

- Installed Chrome extensions in the same existing profile; Safe mode for Tabora. Fresh task-owned tabs/sessions, explicit cleanup, no vault use or credentials supplied to models. Browser profile isolation was not enforced.
- One repetition per configuration; configuration order rotated per task. Ten cases attempted for each product. I09 excluded for all because TinyMCE explicitly disabled editing after exhausting the remote site quota. No substitute task or bypass was used.
- Official participant: the calling Codex agent drives the installed official ChatGPT/Codex Chrome extension through CUA. The browser backend model is not attested. This is not a measurement of standalone ChatGPT autonomous mode.
- Tabora participant: installed extension + native host + `browser_run_start` internal raw-goal controller. Public goal only, no workflow steps, expected answers, task-specific selectors or hidden fallback. The adapter is [internet-installed-adapter.mjs](../../scripts/internet-installed-adapter.mjs).
- Jev latest resolved to jev-1.13.0 in decision traces; Codex used gpt-6-luna via SDK. I01 Jev failed before model inference on initial readiness. Configuration/catalog changes were outside the clock. No product code or controller fixes were made during evaluation.
- Clock includes tab/session setup, model decisions, browser actions, observations and terminal response. Official timing also includes calling-agent and tool orchestration; internal timing uses a neutral process clock. These are different product paths, not an isolated browser executor comparison.
- Deadline 120 s; internal controller limited to 30 steps with approximately 105 s available after adapter setup. No common official step limit was enforced. A failure or request for user help receives 120 s in the failure-penalized mean. This penalty is a scoring convention, not measured runtime.
- Original official I01 timing was invalidated for operator preparation, and original I08 for context-recovery interruption. Both original records were retained privately; replacement runs are used. Product failures were not retried or discarded.
- Post-terminal Tabora state was captured without acting on the page. The observer shares the candidate extension transport; it is not an independently attested oracle. Official outcomes were verified through its browser state. The calling agent had prior context; model context was not equalized.
- Evidence hashes identify private raw records, which are not published because they include local session information. Sanitized [JSON](internet-2026-10-04.json) includes all 30 episodes, exclusions, public goals and aggregate arithmetic. This publication permits arithmetic inspection, not independent replication of private evidence.
- The externally hosted pages can change; source revision and environment images were not pinned. This small single-run pilot does not cover uploads, authentication, vision, downloads, multi-tab workflows or every extension capability.

## What the failures show

The tested internal controller is substantially less capable than the external calling agent. This is not proof that every Tabora MCP action is broken. The experiment evaluates the current internal controller as a product path.

- The offered operations do not cover all needed controls, including checkbox and iframe interactions.
- Currency-valued table ranking does not yield a valid answer choice, so both internal models request help.
- Successful page actions do not reliably produce a goal-completion choice. Luna reached the requested state in I03, I06 and I07, then continued or requested help.
- Asynchronous control changes are followed by actions before the target becomes ready.
- Unrelated page links remain decision candidates; exact-origin enforcement correctly blocks resulting out-of-scope navigation, but the run fails.
- Add/remove requires tracking how many operations were performed and the desired terminal state; the current controller repeatedly loops.
- Jev I01 initial readiness timed out before any decision. Recovery behavior is part of product reliability and this failure remains in the score.

Before presenting Tabora as a general autonomous replacement, improve action coverage, generic goal-state verification, semantic waits, scoped action selection and recovery, then rerun unchanged tasks. Do not encode these task answers or selectors into the controller.
